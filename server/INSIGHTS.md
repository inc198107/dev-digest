## What Doesn't Work
<!-- Dead ends and anti-patterns. The most skipped section and the most valuable one. -->
- 2026-11-21 · src/platform/resilience.ts `withTimeout`, src/platform/jobs.ts JobRunner · Do not treat `withTimeout` as cancellation; if work must really stop, pass an `AbortSignal` into the handler — it is only `Promise.race`, so after `TimeoutError` the work keeps running (repro: 200 ms task under a 50 ms timeout still completed), JobRunner marks the job `failed` and frees the queue slot while the handler continues, and `withRetry` never retries it (`TimeoutError` has no `status`/`code`).
- 2026-11-27 · Skills Lab control experiment (`db/seed-refund-pr.ts`, `TEST_QUALITY_REVIEWER_PROMPT`) · Don't build a "without skills" baseline on a single happy-path test or on a negative scope rule — `deepseek/deepseek-v4-flash` flagged the untested throws in 3/3 runs even with "do not report missing tests" (it downgraded them to SUGGESTION at best). What separated the runs: a suite of several tests that all walk the same branch (no skills: 0–3 SUGGESTIONs, score 91–100, rounding remainder never found; with the 4 skills: 6–7 WARNINGs on production lines, score 16–37, +1257 prompt tokens) plus a prompt that offers the summary as the outlet for coverage remarks.

## Tool & Library Notes
<!-- Dependency quirks: versions, flags, platform issues. -->
- 2026-11-25 · server/ with pnpm v11 · Call binaries as `./node_modules/.bin/<tool>` when you pipe their output — `pnpm exec` first prints "Already up to date / Done in 27ms using pnpm v11.22.0" to stdout, so `pnpm exec depcruise --output-type json | node -e 'JSON.parse(…)'` failed with `Unexpected token 'A', "Already up"…`.
- 2026-11-25 · fastify-type-provider-zod 4.0.x `serializerCompiler` (dist/src/core.js:89) · Before adding a `response` schema to an existing route, check that every returned value satisfies it (enums like `provider`, `.int()` numbers, nullish fields) — the serializer safeParses the payload and throws `ResponseSerializationError`, which `app.ts` turns into a 500, so a schema stricter than the data breaks a working route; fields not in the schema are dropped silently.
- 2026-11-25 · zod 3.25.76 `z.union` of `.strict()` objects (`AgentSkillsBody`) · Don't expect the union's `errorMap` message for a body that mixes both shapes — it fails with the first option's `unrecognized_keys` ("Unrecognized key(s) in object: 'skill_id'"); the custom `invalid_union` message appears only when no option matches at all (e.g. `{}`). Checked with node against server/node_modules/zod.
- 2026-11-27 · drizzle-orm 0.38.4 + postgres 3.4 (`modules/skills/repository.ts` `isDuplicateName`) · Detect a unique violation by `err.code === '23505'` and `err.constraint_name` on the thrown error itself — 0.38 has no `DrizzleQueryError` wrapper (only `DrizzleError`/`TransactionRollbackError` in `drizzle-orm/errors`), postgres-js' `PostgresError` reaches the caller as is; keep a `cause` fallback for the wrapper newer drizzle versions add.
- 2026-11-27 · fflate 0.8.3 `Unzip` + `UnzipInflate` (`adapters/archive/zip.ts`) · Cap unpacked bytes by pushing the archive in small slices (4 KiB) and stopping the loop on overflow — the sync `UnzipInflate` has no `terminate` (the file's `terminate()` is a no-op for it), so one `push(whole, true)` inflates a whole zip bomb (1 MiB of deflate ≈ 1 GiB) before `ondata` can refuse it; `unzipSync(…, { filter })` lists the central directory without inflating anything, but calls `filter` once per record the archive *declares* — count the calls and throw past a cap (a crafted 98-byte ZIP64 declaring 2^32 − 1 records made 3,000,000 calls in 182 ms before the cap was added). (replaces 2026-11-27: the old text said `filter: () => false` simply lists, which hid the record-count OOM)
- 2026-11-27 · js-tiktoken `encode` (`adapters/tokenizer/index.ts`) · Count untrusted text (skill bodies) in bounded slices (`encodeSlices`, ≤ 256 chars, cut at whitespace) — BPE merge is quadratic in one long whitespace-free pre-token; with slices 20,000 × "a" counts in ~0.4 s (test `tokenizer-slices.test.ts`)
- 2026-11-27 · JS RegExp on untrusted lines (`modules/skills/domain.ts` frontmatter) · Never write `[ \t]*(.*)$` — `.` stops at U+2028/U+2029, `$` then fails and the blank run is split every way: 20k spaces + U+2028 = 142 ms, 40k = 552 ms (quadratic); `([\s\S]*)$` + `trim()` takes ~0 ms
- 2026-11-27 · Edit tool / heredocs writing `\uXXXX` into TS sources · Grep for literal invisible characters after writing escapes (`grep -nP "[\x{200B}-\x{200F}\x{202A}-\x{202E}\x{FE00}-\x{FE0F}\x{FEFF}]"`) — the Edit tool and Python one-liners turned `\u200B`, `\u202E`, `\uFE0F` in tests and regexes into the literal characters, invisible in diffs; fix with a node script that re-escapes them
- 2026-11-27 · node:net `BlockList` (Node 24, `adapters/web/text-fetcher.ts`) · Block private ranges with IPv4 subnets only and never add `::ffff:0:0/96` — `check('::ffff:127.0.0.1', 'ipv6')` already matches the IPv4 rule `127.0.0.0/8`, and the /96 subnet makes `check('8.8.8.8', 'ipv4')` true too, i.e. blocks every IPv4 address (checked with node in this session).
- 2026-11-27 · `pnpm db:migrate` on the dev DB · Ignore the logged object with `severity: 'NOTICE'`, `code: '42710'`, `routine: 'transformCreateStmt'` — it is `extension "vector" already exists, skipping` from migration 0000 and prints before `✓ migrations applied`; it looks like a stack-trace error in the tail of the output but nothing failed.

## Recurring Errors & Fixes
<!-- Error message → cause → fix. -->
- 2026-11-22 · src/modules/reviews/diff-loader.ts `loadDiff`, src/modules/pulls/routes.ts `GET /pulls/:id` · Call `GET /pulls/:id` (or open the PR page) before `POST /pulls/:id/review` on a freshly polled PR — polling does not fill `pr_files`, only the detail route does, and the clone lacks the PR head SHA, so the run reviews an empty diff (trace "Diff ready — 0 changed file(s)", ~7k tokens in) and the agent approves with score 100; after one GET the same run sent 58k tokens.
- 2026-11-21 · `pnpm dev` (tsx watch) · Do not `git stash` in this tree while the dev API runs, or `touch src/server.ts` afterwards — `tsx watch` restarted on the stashed (old) sources and did not restart again after `stash pop`, so the API silently served old code (symptom: responses lacked the new `cost_usd` field); after pulling a schema change also run `pnpm db:migrate`, or the reloaded API fails on the missing columns.
